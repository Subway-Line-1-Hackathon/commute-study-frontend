# 프론트엔드 구조 안내

## 실행과 검증

```sh
npm run dev
npm test
npm run lint
npm run build
```

패키지 추가나 버전 변경 없이 기존 React, Zustand, Vite와 Node.js 테스트 러너를 사용합니다.

## 데이터 모드와 인증

`lib/runtime.js`의 `isServerMode`가 서버/Mock 모드를 결정합니다. `VITE_DATA_MODE=mock|server`로 지정할 수 있고, 비워 두면 기존처럼 Supabase 설정이 있을 때 서버 모드로 실행합니다. 명시적 서버 모드에는 Supabase 설정이 필요합니다.

- 화면·자료·세션 코드는 데이터 모드를 확인하며 인증 SDK를 직접 참조하지 않습니다.
- `lib/supabase.js`는 인증 클라이언트만 생성합니다.
- `main.jsx`가 `createTokenProvider`를 API 클라이언트에 연결합니다. 요청 시점의 계정 ID를 토큰 조회 전에 캡처해, 토큰을 기다리던 중 다른 계정으로 바뀌면 요청을 거부합니다. 모듈을 import하는 순서로 인증 헤더가 달라지지 않습니다.
- `AuthBoundary`는 `/home` 같은 직접 진입도 포함해 모든 주소에서 인증을 먼저 확인합니다.
- `lib/authController.js`가 실제 세션, 계정 전환, 로그아웃, 초기화 재시도와 오래된 인증 응답 무효화를 담당합니다. 같은 계정의 토큰 갱신은 화면을 다시 마운트하지 않습니다.
- 게스트 인증 API는 아직 구현하지 않았습니다. 추가할 때 데이터 모드와 별개로 토큰 공급자와 인증 초기화 연결을 변경할 수 있습니다.

## 상태와 요청

- `store/useAuthStore.js`: 프로필·통학 설정·로그인 액션.
- `store/resetUserData.js`: 계정별 자료·세션 백업과 복원, 이전 계정 요청 무효화.
- `store/useMaterialStore.js`: 자료 상태와 업로드·분석 진행. 업로드 큐와 polling 목록은 스토어 안에서 관리합니다.
- `store/material/queries.js`: 과목·자료·단원 조회와 서버 응답 변환.
- `store/material/selectors.js`: 화면용 자료 묶음·단원 목록 계산. 기존 `useMaterialStore` 경로에서도 재노출하므로 화면 import는 유지됩니다.
- `store/useSessionStore.js`: 하나의 영속 스토어를 구성하고 `session/`의 생성·채점·종료·동기화 액션을 조합합니다.

자료 요청은 시작 시점의 요청 세대를 캡처합니다. 계정 전환·로그아웃·탈퇴가 발생하면 세대가 바뀌어 이전 응답과 대기 중인 업로드가 새 상태에 반영되지 않습니다. A → B → A 전환도 같은 방식으로 구분합니다.

## 답안과 저장 실패

단답형 입력 제한은 `lib/answer.js`의 30자 상수를 사용합니다. 채점 전 검증을 통과한 동일한 답안을 로컬 기록·API 저장·자가 판정에 사용하며 초과한 값을 몰래 잘라 채점하지 않습니다.

`lib/storage.js`는 브라우저 저장이 실패해도 메모리의 최신 값과 계정별 백업을 유지합니다. `StorageNotice`가 실패를 안내하고 저장 재시도를 제공합니다. 복구 전에는 **메모리 값이 새로고침이나 탭 종료를 견디지는 못합니다**. 서버 전송 큐의 실행은 저장 실패 때문에 중단되지 않습니다.

## 라우팅

`AppRouter`는 로그인 필요/온보딩 완료 필요 라우트를 그룹으로 묶습니다. 화면 모듈은 `lazy`와 `Suspense`로 필요할 때 불러옵니다. 접근 가드는 필요한 인증 필드만 구독합니다.

## 테스트

`tests/*.test.cjs`는 실제 액션·컨트롤러 소스를 실행하고 외부 API·브라우저 저장소를 대체합니다. 인증 초기화 경쟁, 계정 전환 중 응답, 미전송 답안 보존, 단답형 경계값, 저장 실패 복구, 타이머 종료를 회귀 검증합니다. 실제 OAuth·백엔드와 연결한 브라우저 검증은 별도로 수행해야 합니다.
